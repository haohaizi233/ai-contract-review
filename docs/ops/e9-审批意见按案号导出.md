# e9（泛微）审批意见按案号导出 —— 使用说明

> 用途：把 OA 流程的审批意见**按案号逐个导出为 Markdown**，格式与前端一致
> （意见富文本原样保留：粘贴的合同条款截图、表格、加粗/下划线/红字等样式）。
> 工具：`scripts/e9_opinion_export.py`（凭据走用户环境变量，不写死在代码里）。

## 1. 数据源（重要：e9 不是 Flowable）

ecologyE9 的审批意见存在**自有 workflow_* 表**，不是 Flowable 的 `ACT_HI_COMMENT`
（后者是 Flowable 引擎的表，e9 库里没有；Flowable 分析见 `docs/flowable/`）：

| 内容 | 表.字段 |
|---|---|
| 案号/单号 | `workflow_requestbase.requestmark` |
| 标题/发起人/日期/状态 | `workflow_requestbase.requestname / creater / createdate / status` |
| **审批意见正文** | `workflow_approvelog.remark`（rich HTML，含 `<img>` 截图） |
| **流程流转意见** | `workflow_requestLog.remark`（同上，含提交/转发等 logtype） |
| 环节名称 / 人名 / 流程名 | `workflow_nodebase.nodename` / `HrmResource.lastname` / `workflow_base.workflowname` |

意见里的图片是 OA 内部地址（`/weaver/weaver.file.FileDownload?fileid=…`），
导出时用 `--oa-base http://<OA站点>` 改写成绝对地址（本环境 OA 在 `http://<OA_HOST>:8088`，
80 端口是坏代理会 502）。

### 图片下载/嵌入现状（实测）

- 图片**实体存放在 OA 服务器磁盘**（`ImageFile.filerealpath`，如 `E:\OAbackup\file\OAfile\2026xx\...`），
  数据库里只有路径与元数据（`imagefile` 二进制列为空）；
- `FileDownload` **需要网页登录态**：匿名访问返回 500（数字/十六进制 fileid 均如此）；
  本机也无 SMB 共享权限（445 不通）；
- 因此当前导出为"**链接版**"：`<img src>` 已带绝对地址，浏览器登录 OA 后可直接显示；
  **嵌图版**（图片下载到本地 `images/` 并改为相对路径，离线可看）待补——
  需要网页登录账号或浏览器 Cookie（`ecology_JSessionid`），拿到后在导出命令加
  `--oa-base` + 登录态即可（工具保留该扩展点）。

## 2. 用法

```powershell
# 先把凭据注入进程环境（用户级环境变量已有 DB_HOST/DB_PORT/DB_USER/DB_PWD_READONLY）
foreach ($k in "DB_HOST","DB_PORT","DB_USER","DB_PWD_READONLY") {
  Set-Item -Path ("env:$k") -Value ([Environment]::GetEnvironmentVariable($k,"User"))
}

# ① 合同类流程、某时间段、取 30 个案号（本次演示用的就是这条）
python scripts/e9_opinion_export.py --workflow-like 合同 --from-date 2026-09-01 --limit 30

# ② 指定案号（可多个）
python scripts/e9_opinion_export.py --requestmark CIPCX2026GY00285-1 BQ2026GY00227

# ③ 案号前缀批量（如全部 CIP 系列）
python scripts/e9_opinion_export.py --requestmark-prefix CIPCX2026 --oa-base http://<OA站点>

# ④ 最近 100 个有案号的单
python scripts/e9_opinion_export.py --recent 100

# ⑤ 全量（谨慎：案号数万级，会跑很久、生成海量文件）
python scripts/e9_opinion_export.py --limit 0
```

其他参数：`--to-date`（止）、`--out`（输出目录，默认 `data/e9-opinion-export/`）、`--workflow-like`（流程名包含）。

## 3. 输出

- `data/e9-opinion-export/<案号>.md`：一案一号文件——
  头部信息表（案号/流程/标题/发起人/日期/状态/意见条数）+ 按时间顺序编号的审批意见
  （`### N. 环节 · 审批人 · 时间` + 原始富文本，与前端显示一致）；
- `data/e9-opinion-export/_index.csv`：全部案号的汇总索引（案号/标题/流程/日期/意见条数/文件名）。

## 4. 安全与性能注意

- 导出目录在 `data/`（.gitignore 内），**公司数据不入库、不进 GitHub**；
- 只读账号即可；查询按 `requestid` 走索引（逐单取数快），
  **不要对 remark 大字段做全表过滤**（`workflow_requestLog` 百万级行会超时）；
- 3.6M 行的 `workflow_approvelog` / `workflow_requestLog` 全量导出请用
  `--from-date/--to-date` 或案号列表分批跑。
