# e9 附件下载失败与"HTML 假文件"问题诊断（2026-11-01）

> 结论先行：**93% 的附件根本没有下载成功**——13260 个"已下载"文件其实是 21181 字节的
> "对不起，您暂时没有权限！"错误页存成了 .doc/.pdf/.png；另有 19982 个 fileid 在 md 里
> 标记"下载失败"。根因是**当前 OA 账号（3426/邹依柔）对这些附件没有下载权限**，
> 不是 Cookie 失效、不是 URL 构造错误。换有权限的账号（或给 3426 授权）即可重下。

## 1. 数据现状（data/e9-opinion-export/）

| 项 | 数量 | 说明 |
|---|---|---|
| 本地附件文件 | 15490 | 其中 **13260 是 HTML 假文件**（21181 B 错误页），真实文件仅 ~2230 |
| md 内 FileDownload 失败链接 | 19982 唯一 fileid | md 中保留远端 URL + `**下载失败**` 标记 |
| 受影响案号（含假文件） | 1127 | `e9_attach_repair.py` 干跑统计 |

注意：md 里凡成功下载的写本地相对路径 `attachments/…`，失败的写远端 `FileDownload?fileid=N`
链接，所以**看 md 时"有本地文件 ≠ 有真文件"**。

## 2. 鉴权排查过程（全部已验证）

1. **Cookie 是好的**：`api/portal/quickSearch/getQuickSearchTypes` 返回正常数据；
   登录身份为 3426（HrmResource.id=3331，邹依柔，电通四部电学组，seclevel=10）。
   新旧两份 Cookie（data/.e9_cookie 与其 .bak）实测下载结果完全一致。
2. **失败形态**：`GET /weaver/weaver.file.FileDownload?fileid=N` → HTTP 200 + `text/html`
   21181 字节整页，正文"**对不起，您暂时没有权限！**"（注意与未登录时的 235B 登录跳转页
   是两种不同的错误页）。
3. **同一个请求里有的能下有的不能**（requestid=1231910：fileid 299892 可下，297063 无权限），
   说明是**按文件（其归属文档）鉴权**，与请求/账号无关。
4. **排除的绕过路径**（全部无效）：
   - `download=1 / fromrequest=1 / requestid / f_weaver_belongto_userid` 各种组合；
   - `file_download_permission` 表里的 `uuid` 当 token 传（token/authStr/uuid 参数都试过）；
   - `localStorage.access_token`（该键在本部署中不存在）；
   - `ImageDownload / FileDownloadByToken / DocDsp.ext / api/doc/acc/download` 等备用入口
     （500 或 404）；
   - 带 authStr/authSignatureStr 的签名 URL：需要先打开流程详情页取签名，但
     `ViewRequestForwardSPA.jsp` 对 3426 直接报"您所请求的网页出现异常"（她看不到这些流程）。
5. **权限模型定位**（ecology9 文档模块）：附件下载权由 `DocShare`（文档共享）∪
   `DocSecCategoryShare`（目录共享）决定；角色 26"超级管理员"成员（胡海国/段灿艳等）
   及用户 2190/1792/6/163 在多个受限目录的共享规则里有 `downloadlevel=1`。
   3426 不在这些共享名单内，也不在相关流程的 `workflow_currentoperator` 参与人名单内。

## 3. 修复路线

**一键修复（已就绪）**：`scripts/e9_attach_redownload.py` —— 流式扫描全部 md，
重下"下载失败"链接与本地假文件，成功则回填本地链接，无权限则删除假文件、行内改回
远端链接并记入拒绝缓存（`data/_dl_denied.txt`），换到有权限的账号后
`--retry-denied` 全量重试即可补齐：

```powershell
python scripts/e9_attach_redownload.py                # 全量（幂等可续跑）
python scripts/e9_attach_redownload.py --retry-denied # 换有权限账号后重试被拒的
```

补充路线：

1. **换有权限的账号**：用管理员或共享名单内的账号在 Chrome 里人工登录 OA
   （登录页有验证码，无法脚本化），然后：
   ```powershell
   python scripts/e9_cookie_cdp.py --port 9222 --verify   # 刷新 data/.e9_cookie
   python scripts/e9_attach_redownload.py --retry-denied  # 重试被拒的
   ```
2. **给 3426 授权**：让 IT 在受限目录（审批合同流程 1112 / 专利立案流程 1156 /
   财务类流程 20 / 专利中心技术支持 30 等）的共享规则里加 3426 且 `downloadlevel=1`。
3. **仅链接版交付**：保持 md 现状（远端链接），由有权限的人按 `data/_failed_fileids.txt`
   （19982 个失败 fileid 清单，已生成）自行下载。
