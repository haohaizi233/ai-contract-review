# 两库合并修复工具

`contract_merge_repair.py` 从前版合并索引、逐申请 MD/关系账本、旧 OA MD 和双表日志组装资料卷。输出包括逐申请完整正文、旧表单补充、资源引用与独立缺口台账。

重建命令（在仓库根目录运行）：

```powershell
python tools/contract_merge_repair.py --refresh-oa --out data/contract_merged_next
python tools/validate_contract_merge_repair.py data/contract_merged_next
```

输出目录必须不存在。正式切换后自动从 `data/contract_merged_baseline_20261105` 读取原合并索引；可用 `--legacy` 指定其他前版输入。`--refresh-oa` 仅只读补取缓存不足请求的两张审批日志表，增量缓存独立存放，不写生产库。

`export_merge_supplement.py` 使用现有逐案导出器读取 `data/contract_merge_supplement_scope.csv` 的 101 个补充申请，输出独立目录 `data/contract_merge_supplement`，不覆盖此前 17591 案。默认不再次补抓失效附件。

边界：

- 合同编号仅为汇总分组；同号申请逐条保留，无编号申请以申请 ID 单独建卷。
- 来源正文、申请状态和冲突分别保留，未用统一推测状态替换原值。
- 资源实体按类型和 SHA256 去重，保留每处引用；图片实际转换为 PNG。
- 前版资源仍可访问，但未经来源证明的一律标候选，不作为业务完整证据。
- 主表不再输出未经证明的“审批意见总数”；逐条审批及事件按来源显示，不用 requestid 数量代替。
- 源站缺失、权限失败、未导出旧表单等作为缺口保留，不推断源数据不存在。
- 正文中来源 `.md` 链接用于溯源，依赖原始 `tender-case-export`、`contract_merge_supplement` 和 `e9-opinion-export` 目录；本地附件和图片实体已收敛至合并输出目录。

回归：`python tests/test_contract_merge_repair.py`（内置入口，无需 pytest）。
