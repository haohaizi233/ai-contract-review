# Phase 16-S: 11 - 已知局限性与后续演进建议 (Known Limitations)

## 1. 架构与工程已知局限性

### 1.1 Nonce 单机内存与多实例同步边界
- **现状**：
  当前 `InMemoryAndDbNonceStore` 优先使用带全局互斥锁与 TTL 自动清理的内存集合记录 Nonce。当配置了数据库存储 (`storage.record_and_check_nonce`) 时，支持向底层关系数据库的 Nonce 表原子写入实现多实例去重。
- **局限**：
  在未配置数据库的单机模式下，若服务发生冷重启，服务启动前的 300 秒时间窗口内若受到重放攻击，内存中已消费的 Nonce 记录将重置。
- **演进建议**：
  生产多实例集群部署必须显式挂载共享 PostgreSQL 或 Redis 作为集中式分布式 Nonce 存储介质。

### 1.2 外部大模型推理质量与离线安全回退
- **现状**：
  当外部大模型不可用（如网络断开、超时、未授权出境门禁拦截 `CONTRACT_KB_ALLOW_EXTERNAL_LLM=0`）时，系统平滑降级至规则初筛模式（`RULE_REVIEW_COMPLETED`），并明确标注“大模型语义审查未执行”。
- **局限**：
  确定性规则初筛依赖预设的标准母本差异与已审批红线，对于非预设类别的复杂长文本自然语言语义偏离（如隐蔽免责声明、交叉引用矛盾），规则引擎无法提供如 LLM 一般细致的法理剖析。
- **演进建议**：
  部署本地可信私有化大模型（如私有化部署的 Qwen-35B 或 DeepSeek-R1 本地实例），消除对公网外部 LLM API 的依赖。

### 1.3 训练数据导出脱敏与格式
- **现状**：
  当前 SFT 训练集导出实现了严格的租户作用域过滤和人工审批门禁，并按合同哈希切分训练集与评估集以防数据穿透泄漏。
- **局限**：
  目前数据持久化基于受控文件系统 JSONL。当历史反馈数据累积至百万级别时，大文件并发追加写入与全量检索导出会面临 I/O 瓶颈。
- **演进建议**：
  后续演进中将 SFT 数据流管道迁移至专业的数据治理平台（如基于 PostgreSQL + pgvector 或专有微调数据仓库）进行版本化管理。

### 1.4 会话协作授权白名单
- **现状**：
  当前会话强绑定 `(tenant_id, user_id)`，同租户不同用户完全无法互相访问彼此的审查任务，保障了用户合同隐私。
- **局限**：
  在实际企业法务团队中，法务主管或协作律师可能需要介入复核下属的审查任务。目前此类场景仅支持 `user_id="system_admin"` 超级管理员介入。
- **演进建议**：
  在会话实体中增加 `collaborators: list[str]` 细粒度授权协作名单。
