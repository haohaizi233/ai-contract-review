# 合同审查三栏滚动协调调研与修复（2026-11-10）

## 原实现的问题

- claimDriver 仅在没有驱动栏时接管，以 140ms 定时器释放；快速换栏的真实手势被旧栏锁阻挡。滚动条拖动、键盘也没有接管入口。
- 正文滚动按像素复制；批注反向联动按最近卡片跳到条款顶部，两个方向不连续。
- offsetTop 属于 offsetParent 坐标，不能直接当成滚动容器内坐标；点击定位也有同一问题。
- 滚动过程中反复 scrollIntoView(smooth) 会启动新的异步滚动，且可能影响外层滚动容器。
- 每次滚动遍历批注和条款并交错读写布局，增加长合同的主线程负担。

## 采用方案

保留浏览器原生滚轮/触控板滚动，不 preventDefault，不添加模拟惯性。手势发生在哪一栏，该栏立即成为唯一驱动源；程序写入的从栏位置不会反向驱动。点击定位有单独状态，可被真实输入打断，并遵循减少动态效果的系统偏好。

左右正文以对应条款建立锚点；正文与右栏以实际可见卡片和所属条款建立锚点。锚点之间做分段线性插值；加入首尾边界，处理短内容、空筛选、重复/乱序锚点。筛选或异步展开后重建测量缓存。一个条款有多条批注时，重复正文锚点保留首个可用点，保证映射单调。

滚动帧内只查缓存并二分定位，合并从栏写入。ResizeObserver、MutationObserver、窗口尺寸和字体加载用于使缓存失效。MutationObserver 不监听高亮 class，避免把高亮变更当作布局变更。重新渲染后解除旧卡片监听。

## 官方资料及对本项目的意义

- [MDN：scroll event](https://developer.mozilla.org/en-US/docs/Web/API/Document/scroll_event)：高频事件中应减少昂贵工作；rAF 与滚动事件频率相近，不能把 rAF 本身当作降频。本次主要收益来自缓存几何和去除逐帧全量遍历。
- [Chrome：默认快速滚轮](https://developer.chrome.com/blog/scrolling-intervention-2/)：不必要的可取消滚轮监听会阻塞浏览器滚动；本次保持 passive 监听。
- [MDN：scrollTop](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollTop)：滚动值可能为小数，部分环境有越界值；本次使用容差并夹取边界。
- [MDN：scrollIntoView](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollIntoView)：该 API 可能影响多个祖先滚动容器；本次点击仅对目标栏调用 scrollTo，普通联动不用 smooth。
- [MDN：ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)：用于响应元素尺寸变化，覆盖卡片展开和容器尺寸变化。
- [W3C：CSS Overscroll Behavior](https://www.w3.org/TR/css-overscroll-1/)：用 CSS 控制滚动链；本次三栏设置 contain，防止边界处把滚动传到外层页面。

上述协调算法是结合本项目结构得出的工程方案，并非浏览器规范规定的唯一算法。

## 验证及边界

- Node 执行页面实际内联控制器，覆盖插值、边界、从栏防回灌、立即接管、右栏小步连续性、导航隔离、空筛选、零滚动范围、尺寸变化。
- 页面/API 与控制器回归测试共 12 项通过；Python 编译与改动空白检查通过。
- Edge headless 真实 DOM 布局测试（24 条不等高条款、24 张卡片）通过：联动、防回灌、接管、连续性、首尾对齐。通过 CDP 等待真实帧；dump-dom 的虚拟时间模式会跳过部分动画帧，不能用于此项判断。
- 浏览器测试使用合成手势与程序滚动，不代表物理鼠标/触控板手感验收。未测量真实业务大合同的 FPS、输入延迟和不同刷新率；不声称达到特定帧率。
